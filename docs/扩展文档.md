# 扩展开发文档

面向二次开发者，讲解工程架构、模块通信机制与常见扩展场景的落地步骤。

## 1. 分层架构

```text
┌──────────────────────────── UI 层（src/ui） ───────────────────────────┐
│ Toolbar / TreePanel / DataPanel / LogPanel / InfoModal / GuiPanel /    │
│ StatusBar / UIManager        只读写 DOM + 订阅/发布事件，不含 3D 逻辑   │
└───────────────▲───────────────────────────▲───────────────────────────┘
                │ EventBus 事件               │ 直接调用（仅 UIManager 总装）
┌───────────────┴───────────────────────────┴───────────────────────────┐
│ 交互层（src/interaction） Picker 射线拾取 / LabelManager 空间标签       │
├────────────────────────────────────────────────────────────────────────┤
│ 仿真层（src/simulation） DampedJoint / SimulationEngine /              │
│                          Visualization / PhysicsBridge                 │
├────────────────────────────────────────────────────────────────────────┤
│ 模型层（src/model） ModelLoader 远程加载 / PartRegistry 部件注册 /      │
│                     ProceduralModel 兜底模型                           │
├────────────────────────────────────────────────────────────────────────┤
│ 渲染层（src/render） RendererManager / LightingRig / CameraController / │
│                      PerformanceMonitor                                │
├────────────────────────────────────────────────────────────────────────┤
│ 核心层（src/core） Engine 总装主循环 / EventBus / Logger                │
└────────────────────────────────────────────────────────────────────────┘
```

依赖方向**自上而下**：上层可以依赖下层，下层不 import 上层文件；
跨层协作一律走 `EventBus`，保证模块可独立替换与单元测试。

## 2. 事件总线机制（`src/core/EventBus.js`）

全局单例 `bus`，API：`on / once / off / emit`。事件名常量集中在文件头部注释维护：

| 事件 | 发布者 | 监听者 | 载荷 |
| --- | --- | --- | --- |
| `model:loaded` | Engine | 渲染器、UI、拾取、标签 | `{ root, registry, isFallback }` |
| `sim:running` | SimulationEngine | Toolbar、GuiPanel | `boolean` |
| `sim:step` | SimulationEngine | DataPanel | 完整状态快照 |
| `sim:mode-changed` | SimulationEngine | 任意扩展 | `'friction' | 'independent'` |
| `sim:log` | Logger | LogPanel | 日志条目 |
| `sim:reset` | SimulationEngine | PhysicsBridge 等 | 无 |
| `part:select` | Picker / TreePanel / Label | InfoModal、Picker、TreePanel | `partId | null` |
| `part:hover` | Picker / TreePanel | Picker 高亮 | `partId | null` |
| `part:visibility` / `part:isolate` | TreePanel | Picker、LabelManager | 部件 ID 等 |
| `render:mode-changed` | RendererManager | StatusBar | 模式字符串 |
| `camera:bookmark` / `camera:tour` | CameraController | GuiPanel | 书签/布尔 |
| `perf:degrade` | PerformanceMonitor | StatusBar | 档位与方向 |
| `physics:toggle` | PhysicsBridge | 任意扩展 | `boolean` |

新增模块时优先复用上述事件；确需新事件，请在 `EventBus.js` 头部注释登记表中追加一行。

## 3. 主循环时序（`Engine._loop`）

每帧严格按以下顺序执行，避免“渲染时仿真状态只更新了一半”：

1. `simulation.update()` —— 固定步长运动学积分（暂停时内部执行缓停积分）
2. `visualization.update(dt)` —— 箭头/轨迹跟随最新位姿
3. `physics.update(dt)` —— 可选 cannon-es 步进并回写网格
4. `cameraController.update(dt)` —— 书签补间、巡检、防穿模
5. `perfMonitor.update(dt)` —— 采样窗口统计与降级决策
6. `rendererManager.render()` + `labels.render()` —— WebGL 后处理与 CSS2D

帧间隔 `dt` 做了 0.05s 上限钳制，防止切换浏览器标签页回来后产生大步长跳变。

## 4. 常见扩展场景

### 4.1 新增一种渲染模式（如“热力温度模式”）

1. 在 `RendererManager.js` 的 `RenderMode` 增加枚举（如 `THERMAL: 'thermal'`）
2. 在 `_applyRenderMode` 分支中实现材质策略（可替换为自定义 ShaderMaterial，
   注意同步在 `_snapshot/_restoreMaterials` 中处理还原）
3. 在 `GuiPanel` 的“④ 渲染与画质”下拉选项中追加一项
4. `getModeLabel` 补中文名，状态栏自动生效

### 4.2 新增一个部件类型（如“安全联锁门”）

1. `PartRegistry.js` 的 `PART_DEFS` 增加 defId、中文名、分类；
   若按杯位模板实例化，加入 `TEMPLATED_PARTS`
2. 模型节点按命名规范增加对应节点（见模型制作规范）
3. `public/config/parts.info.json` 增加同名 key 的科普文案
4. 若该部件参与运动：在 `SimulationEngine.init` 中为其创建 `DampedJoint`，
   并在 `_integrate` 中写入目标速度与场景节点
5. 无需改 UI：部件树、拾取、弹窗会自动收录新部件

### 4.3 新增一个数据指标（如“摩擦轮打滑率”）

1. 在 `SimulationEngine._refreshVisualData` / `getState` 中计算并挂到状态快照
2. `DataPanel._render` 增加一行展示
3. 若需写日志：调用 `logger.info(...)`，CSV 导出自动包含

### 4.4 新增一个 UI 面板

1. 在 `src/ui/` 新建模块，构造函数接收需要的引擎模块，`bind()` 中订阅事件
2. 在 `index.html` 增加容器节点与 `main.css` 样式
3. 在 `UIManager` 的 `model:loaded` 回调中实例化并 `bind()`
4. 遵守只通过 EventBus 与仿真/渲染通信的约定，不要在 UI 模块里直接改 three 对象

### 4.5 接入真实设备数据（数字孪生）

仿真引擎的输入只有 `setMasterRPM / setCupRPM / setCupEnabled / setMode` 等方法。
新增 `src/io/DeviceAdapter.js`，在 WebSocket/MQTT 消息回调中调用这些方法即可，
SimulationEngine 与渲染层无需任何修改。建议在 Adapter 内做数据校验与断线缓停保护。

### 4.6 替换物理引擎或增加碰撞检测

`PhysicsBridge` 已把 cannon-es 隔离为动态 import 的可选模块。
替换为 rapier 等引擎时，保持 `enable/disable/update/reset` 四个对外方法签名不变，
Engine 与 GUI 无需改动。

## 5. 性能自动降级策略详解

配置位于 `app.config.js → performance`，共 4 档，按以下优先级逐级牺牲画质：

| 档位 | 像素比 | 软阴影 | 阴影贴图 | HDR 环境 |
 | --- | --- | --- | --- | --- |
| 高 | 2.0 | 开 | 2048 | 开 |
| 中 | 1.5 | 开 | 1024 | 开 |
| 低 | 1.0 | 关 | 512 | 开 |
| 最低 | 0.75 | 关 | 512 | **关** |

- 每 3 秒为一个采样窗口；窗口平均 FPS < 30 立即降一档
- 连续 3 个窗口 FPS > 55 才升一档（防抖，避免在阈值附近反复横跳）
- 升降档通过 `perf:degrade` 事件驱动 `RendererManager.applyQuality` 热切换，无需重载
- GUI 可手动锁定档位，锁定后自动策略暂停（`PerformanceMonitor.setAuto(false)`）

进一步优化方向（当前未启用，预留）：实例化杯位网格（InstancedMesh）、
按需关闭阴影投射的小零件、轨迹降采样、HDR 降为 1K。

## 6. 仿真数学模型摘要

- 阻尼关节（缓启缓停）：`ω ← ω + (ω* − ω)·(1 − e^(−k·Δt))`，角度积分 `θ ← θ + ω·Δt`
- 角度限位：积分后钳制 `θ ∈ [θmin, θmax]`，触限速度归零并发布限位状态
- 摩擦联动：`ω_cup_target = ω_disk · i`，`i` 即 `frictionRatio`（教学演示量）
- 独立驱动：`ω_cup_target = RPM(单杯) → rad/s`，杯间完全解耦
- 切向线速度：`v = ω_disk × r`（叉乘，转盘绕世界 Y 轴）
- 固定步长 `1/60s`；单步按钮即精确推进一个步长，便于课堂逐帧讲解

## 7. 代码风格约定

- 全部注释与文档使用中文；标识符使用英文
- 模块文件采用 `大驼峰类名.js`，每个文件一个主导出类
- 构造函数只做字段初始化，异步/复杂初始化放 `init()` 或 `bind()`
- three 对象释放时显式 `dispose()` 几何/材质/渲染目标，避免内存泄漏
- 不引入额外 UI 框架与工具库（lodash 等），保持工程轻量、可读
