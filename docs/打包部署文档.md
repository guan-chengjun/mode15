# 打包部署文档

介绍生产构建、静态服务器部署（Nginx / Apache / IIS）、CDN 与跨域、缓存与升级策略。

## 1. 生产构建

```bash
npm run build
```

构建产物输出到 `dist/`，结构如下：

```text
dist/
├─ index.html
├─ assets/
│  ├─ three-*.js           # three.js 独立分包（长期缓存）
│  ├─ postprocessing-*.js  # 后处理独立分包
│  ├─ gui-*.js             # lil-gui 分包
│  ├─ physics-*.js         # cannon-es 分包（仅开启惯性物理时按需加载）
│  ├─ index-*.js           # 业务代码
│  └─ index-*.css
└─ config/
   └─ parts.info.json      # 科普文案（可单独更新，无需重新构建）
```

构建要点：

- `vite.config.js` 中 `base: './'` 使用**相对路径**，产物可部署到域名任意子目录
- 模型与 HDR 不在 `assets` 中：它们通过 URL 运行时加载，不参与打包（远程加载、不内嵌）
- `assetsInlineLimit: 4096` 保证只有极小资源才内联，避免模型被误打入 JS
- 第三方依赖按 `manualChunks` 分包，业务迭代时用户浏览器可继续缓存 three 等大依赖

本地验证构建产物：

```bash
npm run preview   # 默认 http://localhost:4173/
```

## 2. Nginx 部署示例

把 `dist/` 内容上传到服务器目录（示例 `/var/www/coffee-sim`）：

```nginx
server {
    listen       80;
    server_name  sim.school.edu.cn;
    root         /var/www/coffee-sim;
    index        index.html;

    # 单页应用回退（本项目为纯前端 SPA）
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 带 hash 的静态资源：强缓存一年
    location /assets/ {
        expires 1y;
        add_header Cache-Control "public, immutable";
    }

    # 科普文案：协商缓存，更新后立即生效
    location /config/ {
        add_header Cache-Control "no-cache";
    }

    # 模型与 HDR：建议单独 location，便于配置大文件超时与 CORS
    location /models/ {
        add_header Access-Control-Allow-Origin "*";
        add_header Cache-Control "public, max-age=86400";
    }
    location /hdr/ {
        add_header Access-Control-Allow-Origin "*";
    }

    # 开启 gzip，JS/CSS 体积可再降 60% 以上
    gzip on;
    gzip_types text/css application/javascript application/json image/svg+xml;
    gzip_min_length 1024;
}
```

重载配置：`nginx -t && nginx -s reload`。

## 3. Apache 部署示例

`dist/` 上传到 `htdocs/coffee-sim`，在该目录放置 `.htaccess`：

```apache
# SPA 回退
<IfModule mod_rewrite.c>
  RewriteEngine On
  RewriteBase /coffee-sim/
  RewriteRule ^index\.html$ - [L]
  RewriteCond %{REQUEST_FILENAME} !-f
  RewriteCond %{REQUEST_FILENAME} !-d
  RewriteRule . /coffee-sim/index.html [L]
</IfModule>

# 静态资源缓存
<IfModule mod_headers.c>
  <FilesMatch "\.(js|css)$">
    Header set Cache-Control "public, max-age=31536000, immutable"
  </FilesMatch>
  <FilesMatch "\.json$">
    Header set Cache-Control "no-cache"
  </FilesMatch>
  Header set Access-Control-Allow-Origin "*"
</IfModule>

<IfModule mod_deflate.c>
  AddOutputFilterByType DEFLATE application/javascript text/css application/json
</IfModule>
```

## 4. IIS 部署要点

1. 新建网站指向 `dist` 目录，应用程序池选“无托管代码”
2. 安装 **URL Rewrite** 模块，添加 SPA 回退规则（等价于 `try_files`）
3. 在“HTTP 响应头”中为 `assets` 目录设置长期缓存、为 `config` 设置 no-cache
4. MIME 类型确认存在：`.glb → model/gltf-binary`、`.gltf → model/gltf+json`、
   `.hdr → application/octet-stream`、`.wasm → application/wasm`（DRACO 用）

## 5. 模型/HDR 放 CDN 与跨域（CORS）

模型可以与站点不同源，例如放到对象存储/CDN：

1. 在存储桶开启静态网站托管或 CDN 加速
2. 配置跨域响应头：
   ```text
   Access-Control-Allow-Origin: *
   Access-Control-Allow-Methods: GET, HEAD
   ```
3. 修改 `src/config/app.config.js`：
   ```js
   modelUrl: 'https://cdn.school.edu.cn/models/coffee_cup.glb',
   hdrUrl: 'https://cdn.school.edu.cn/hdr/studio.hdr'
   ```
4. 若对方服务器无法配置 CORS，可在 `vite.config.js` 配置开发代理，
   生产环境则在 Nginx 用 `proxy_pass` 做同源反向代理：
   ```nginx
   location /remote-models/ {
       proxy_pass https://cdn.other-host.com/models/;
   }
   ```

> GLTF 的 `.bin` 与贴图路径是相对 gltf 文件本身解析的，整组文件需保持目录结构一起上传。

## 6. 缓存与升级策略

| 资源 | 缓存策略 | 升级方式 |
| --- | --- | --- |
| `assets/*.js`、`*.css` | 文件名带内容 hash，强缓存一年 | 重新构建自动换文件名 |
| `index.html` | no-cache / 必须协商 | 覆盖即可，用户下次打开拿到新引用 |
| `config/parts.info.json` | no-cache | 直接覆盖文件，刷新即生效，**无需重新构建** |
| 模型/HDR | 可按版本号命名（`coffee_cup_v2.glb`） | 换文件名或更新 `modelUrl`，避免旧缓存 |

## 7. 部署验收清单

- [ ] 浏览器访问站点，加载遮罩正常消失并进入主界面
- [ ] 无模型时兜底模型正常；正式模型放置后正确加载（控制台无 404/CORS 报错）
- [ ] 四种渲染模式切换正常，Outline 高亮与 X 光透视可见
- [ ] 两种传动模式切换、单步、复位功能正常
- [ ] 部件点击弹窗、部件树隔离/隐藏、空间标签正常
- [ ] 日志 CSV 可下载且 Excel 打开中文无乱码
- [ ] 限制帧率（DevTools → CPU 4× slowdown）后状态栏出现自动降级提示
- [ ] 移动端/窄屏下侧栏不遮挡主要操作区
- [ ] HTTPS 站点引用的模型/HDR 均为 https，避免混合内容拦截

## 8. Docker 化部署（可选）

多阶段构建示例 `Dockerfile`：

```dockerfile
# 构建阶段
FROM node:20-alpine AS build
WORKDIR /app
COPY package*.json ./
RUN npm ci
COPY . .
RUN npm run build

# 运行阶段：纯静态文件 + nginx
FROM nginx:stable-alpine
COPY --from=build /app/dist /usr/share/nginx/html
EXPOSE 80
CMD ["nginx", "-g", "daemon off;"]
```

```bash
docker build -t coffee-sim:1.0 .
docker run -d -p 8080:80 coffee-sim:1.0
```
